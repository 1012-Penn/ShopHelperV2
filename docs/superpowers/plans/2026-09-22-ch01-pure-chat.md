# 第一章纯对话实现计划

> **给 Agent 的要求：** 必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans`，逐任务执行本计划。每一步使用复选框跟踪。

**目标：** 实现一个基于 FastAPI + LangChain 的无状态电商客服纯对话 API，支持多轮上下文、SSE 逐 token 流式输出和售后描述结构化提取。

**架构：** HTTP 层只负责请求校验、依赖注入和 SSE 编码；对话 Service 负责 Prompt、历史裁剪和模型流式调用；售后 Service 负责结构化输出；配置层只负责环境变量和模型实例构建。会话历史由客户端传入，本章不引入数据库或 Agent。

**技术栈：** Python 3.10+、FastAPI、Pydantic Settings、LangChain Core、LangChain OpenAI、pytest、httpx。

**Spec：** `docs/superpowers/specs/2026-09-22-ch01-pure-chat-design.md`

## 全局约束

- 应用统一通过 `langchain_openai.ChatOpenAI` 调用 OpenAI-compatible 上游。
- `MODEL`、`API_KEY`、`BASE_URL`、`MAX_HISTORY_TOKENS` 必须由环境变量配置，其中 `DEEPSEEK_API_KEY` 可作为 DeepSeek 的密钥来源。
- 项目 `.env` 优先；当前工作区可回退读取 `/root/.env`，但任何密钥都不得写入代码、日志、测试 fixture 或提交。
- 系统不保存会话状态；`conversation_id` 只用于请求关联和响应回传。
- 不实现工具调用、Agent 循环、数据库、认证、限流或前端页面。
- 每个新增可执行行为都必须先写失败测试并观察预期失败；纯 Prompt 和固定评估数据使用标注样例评估替代 TDD。
- 每完成一个任务都在 `dev-notes/ch01.md` 追加关键原话、产出、用户纠偏、翻车与返工记录，并提交该任务的 Git commit。

## Review Focus

- 空历史、奇数条历史和无法组成完整 human/assistant 对的历史必须被安全裁剪；由 Task 2 的边界测试覆盖。
- 当前用户消息不能因历史预算不足而丢失；由 Task 2 的保留当前消息测试覆盖。
- 上游在已发送 token 后失败时，SSE 必须发出 `error` 事件且不伪造 `done`；由 Task 3 的流式错误测试覆盖。
- 用户输入含换行、引号和中文时，SSE data 必须仍是合法 JSON；由 Task 3 的编码测试覆盖。
- 售后描述缺少订单号或期望方案时，结构化结果必须使用 `null` 而不是臆造值；由 Task 4 的评估样例覆盖。

- 创建：`tests/test_chat_api.py`

**接口：**

- `POST /api/v1/chat/stream` 接收 `ChatRequest`，返回 `EventSourceResponse`。
- token 事件：`event: token`，data 为 `{"content": "..."}`。
- 完成事件：`event: done`，data 为 `{"conversation_id": "..."}`。
- 上游流式异常：`event: error`，data 为安全的错误描述，不包含密钥或完整 prompt。

- [ ] **步骤 1：先写 API 失败测试**

测试使用 FastAPI `TestClient` 和 fake `ChatService`，不访问真实模型：发送两条 history 和当前消息，断言响应 media type 为 `text/event-stream`，包含两个 token 事件和一个 done 事件，并断言 fake service 收到完整 history。

运行：`pytest tests/test_chat_api.py -q`

预期：失败，因为 `app.main` 和路由尚不存在。

- [ ] **步骤 2：实现最小 SSE 路由**

使用 Context7 已核实的 `EventSourceResponse`、`ServerSentEvent`，通过依赖注入提供 `ChatService`。每个 chunk 单独 JSON 编码后发送；正常完成才发送 done。
