# ch06 Formal Workflow Router Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the placeholder workflow router with history-aware query resolution, strict prompt-based intent classification, and a resumable order/policy subflow with chat-native demo forms.

**Architecture:** Extend the current LangGraph workflow in place. Resolve each turn before classifying; route refund/after-sale turns through a persisted order choice, one-time query expansion, mandatory multi-query policy retrieval, evidence deduplication and the existing primary Agent. Keep all demo business data in the application database and the existing SSE chat surface.

**Tech Stack:** Python 3.10+, FastAPI, SQLAlchemy 2, LangGraph 1.2, LangChain 1.4 / langchain-openai 1.6, existing vanilla HTML/CSS/JS, pytest and existing browser/Playwright harness. No dependencies are added.

**Spec:** `docs/superpowers/specs/2026-10-04-ch06-formal-router-design.md`

## Global Constraints

- Do not add Python or npm dependencies.
- Intent JSON has exactly `intent` and `confidence`; intent is one of seven named classes or `其他`.
- Query expansion JSON has exactly one field, `queries`, whose value is an array of strings.
- Complete questions without context-dependent references must pass through byte-for-byte unchanged.
- Only refund/return and after-sale routes expand queries; every query in those routes searches policy before the primary Agent runs.
- Order identifiers must be user-provided or explicitly selected from the fixed demo order list; never generated by a model.
- Keep one canonical knowledge record per source; merge duplicate retrieval hits at request time.
- Use the already configured primary model; do not add a small-model retry path in this chapter.
- Demo order/refund flows must say they are simulated and must never claim to execute a real refund.
- Modify the served native page in `app/static/index.html`; do not build the inactive React page.
- Log each completed phase to `dev-notes/ch06.md` as soon as it finishes.
- Before using FastAPI, SQLAlchemy, LangChain or LangGraph APIs, check their current official Context7 documentation and honor the versions in `pyproject.toml`.

## Review Focus

- A complete question with no reference stays unchanged; an ambiguous demonstrative pronoun with multiple prior topics resolves only from the current conversation. Pin in Task 3 evaluation cases.
- Invalid intent JSON, extra keys, out-of-range confidence and strange questions go to `其他`, without accidentally entering an operational route. Pin in Task 3.
- A repeated/expired/forged order selection or a selection from another conversation never resumes or leaks another run. Pin in Task 5.
- Query expansion failure still searches the canonical refund/after-sale question, while empty/failed policy evidence never reaches the judgment Agent. Pin in Task 4 and Task 5.
- Repeated refund submission request IDs remain idempotent, and frontend double-click/old-card behavior cannot duplicate a request. Pin in Task 2 and browser verification in Task 6.
