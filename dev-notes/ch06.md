## 阶段：回顾性 code review 与修订（2026-10-04）

- 用户关键原话： “需求澄清留在主力 Agent 里做，意图识别只判「要干什么」”；“每一轮意图都判对、指代都补全对”。
- 关键产出：对 spec、plan、评估样例做 Luna 独立回顾评审。评审找到 3 项 Important：8 组会话中只有 5 组真正到第三轮；不可消解指代被规则误兜底为「其他」；订单选择事件缺少可校验的 assistant `message_id`。已据此修订 spec/plan/data：扩至 43 条并确保 8 组均达第三轮；将 `reference_resolved` 与 intent 分开，无历史但可分类的“它多少钱/它能退吗”保留原问句并交主力 Agent 澄清；订单 offer 先持久化并让选择同时绑定 message/request/conversation。
- 用户拒绝/纠偏：接受用户原始需求优先级，不把可识别的业务意图与 referent 是否已消解混为一谈。
- 翻车与返工：计划初版未核实第三轮覆盖数量，且把 unresolved referent 收敛为固定兜底；原选择事件少 `message_id`，无法充分绑定 stale/伪造卡片。修订后重跑 JSON 语法、43 唯一 ID、八类数量、8/8 第三轮覆盖、unresolved 保留原文等断言均通过。第一轮复审确认这些项；随后发现 Task6 前端 payload 未列全绑定字段，现已修订并请求二次复审。
